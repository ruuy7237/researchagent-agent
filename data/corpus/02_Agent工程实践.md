# Agent 工程实践

## 编排形态
常见编排分为单 Agent 循环与多 Agent 协作。多 Agent 常用 Supervisor–Worker 结构：由调度者拆分任务、派发给专职执行者，再汇总结果。相比单 Agent，多 Agent 的优势是职责隔离与错误局部化，代价是通信开销与调试复杂度上升。

## 工具调用
工具调用需要三件事：清晰的工具描述、严格的入参校验、可预期的错误返回。入参校验通常使用 JSON Schema，错误返回应包含可读原因以便模型自我修正。

## 人在环
对不可逆动作（支付、删除、资产转移）普遍设置人工确认。工程上常用三级策略：只读自动执行、写操作建议后确认、高危操作强制人工。

## 评测
Agent 评测关注任务成功率、平均步数、误操作率与人工接管率。仅看成功率会掩盖代价：步数膨胀与人工接管率上升同样意味着产品不可用。
