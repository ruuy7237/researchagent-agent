# ResearchAgent · 调研 Agent

丢给它一个研究命题，它自己拆子问题、检索证据、判断还要不要继续查，最后给出带引用的结论。
证据不够就拒答，几篇资料说法不一致就标"存疑"。

## 能做什么

- **自动拆问题**：把一个大命题拆成几个可以在资料里查到的子问题
- **多轮检索**：查完一轮看新增证据有多少，增益太低就停，不硬跑固定轮数
- **带引用作答**：每句结论后面标 [编号]，能回指到具体文档和段落
- **拒答与存疑**：资料里没有的命题直接说答不了；资料互相矛盾的地方标出来，不假装确定

## 三步跑起来

1. 双击 **`启动.bat`**。第一次会自动建环境装依赖（1-2 分钟），之后直接启动
2. 浏览器打开 <http://127.0.0.1:8013>
3. 关掉黑窗口即停止

跑评测：双击 **`评测.bat`**，30 条命题跑一遍，结果写 `data/metrics.json`。

## 实际跑一遍是什么样

问一个资料里有的（真实输出）：

```
问：大模型应用落地的主要障碍是什么

结论：证据未直接给出"主要障碍"的完整清单，仅能归纳出成本、时延、检索质量与幻觉、
      评测失真、组织编制等若干约束；哪一项是"主要"障碍，存疑。

依据：
1. 成本：推理成本随输入/输出长度与调用次数上升，长上下文与多轮反思显著抬高成本，
   需分级模型路由 [1][2]。
2. 时延：端到端由检索、首 token 生成与流式输出构成，首 token 受模型规模与并发影响 [2]。
3. 检索与幻觉：检索质量决定回答上限，融合不解决"库里根本没有"；幻觉源于检索缺失与生成越界 [4]。
4. 评测：仅看成功率会掩盖步数膨胀与人工接管率上升 [3]。
5. 组织：中小企业常一人承担需求、方案与 Demo，流程完备性让位于交付速度 [2]。
```

注意它没有编一个"主要障碍就是成本"的结论，而是把能归纳的列出来、把"哪个最主要"标成存疑。

问一个资料里没有的：

```
问：特斯拉的市值是多少

答：现有证据不足以回答该问题，建议补充资料或缩小问题范围。
   refused = true
```

## 内部流程

```
    命题
     │
   Plan ── 拆成 2~4 个子问题
     │
  Execute ── 对每个子问题检索 top-k 证据块
     │
  Reflect ── 新增证据 / 已有证据 < 12% ？
     │            │
     │          否 → 只对没覆盖到的子问题换说法再查
     │            │
     └── 是 ──────┴─▶ Report：拼证据 → LLM 生成（带编号引用）/ 抽取式兜底
                          │
                   证据覆盖率 < 0.30 → 拒答
```

没上 LangGraph。这段只有四个节点、没有并行分支，`while` + 覆盖率判断更好读；
有条件边和人在环节点的拓扑才值得上图。

## 分块

语料 4 篇，切完 8 个块，切分 220 字 / 40 字重叠。

一开始沿用 420 / 90，块太大，语料外的问题也能在某个块里凑出不错的覆盖率，闸门拦不住，
拒答准确率只有 25%。改到 220 以后块变多、内容更集中，覆盖率区分度上来，拒答到 100%。

## 接口

```bash
curl -s -X POST http://127.0.0.1:8013/research \
  -H 'Content-Type: application/json' \
  -d '{"question": "大模型应用落地的主要障碍是什么"}'
```

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/research` | `{"question": "..."}` |
| GET | `/health` | 索引块数、是否接了模型 |

## 指标

30 条命题，26 条可答、4 条语料外：

| 指标 | 不配 key（抽取式） | 配 key（deepseek-chat） |
|---|---|---|
| 事实准确率（要点覆盖 ≥60% 算对） | 80.8% | **88.5%** |
| 要点覆盖率 | 82.7% | 88.5% |
| 引用有效率 | 88.5% | 88.5% |
| 拒答准确率 | 100% | 100% |
| 平均轮次 | 1.27 | 1.27 |
| 平均证据块 | 4.9 | 4.9 |
| p50 延迟 | 3 ms | 1.1 s |

引用有效率 88.5% 不是 100%：抽取式在某些命题上拼出来的句子里挂不上编号。这个数没往上调，它就是个缺陷。

## 已知问题

- 语料 4 篇共 1700 字左右，规模太小。只能验证机制跑得通，效果说明不了什么；
- 30 条命题是自己写的，偏要点抽取型，没有需要多跳推理的题；
- 平均 1.27 轮就收敛，说明反思循环在简单题上基本没起作用。要看效果得有更难的题；
- "存疑"靠 prompt 让模型判断，没有单独的冲突检测。
